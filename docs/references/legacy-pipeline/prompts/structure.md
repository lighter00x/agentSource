# 🤖 图像语义理解任务提示词：医药分子结构标识与识别

## 🎯 任务目标

从提供的**分子结构展示图**中，精准识别每一个分子的**化学名称/代号**、**数字编号**及结构检测框的 **mol_id**。

## 📥 输入信息

1. **目标图像**：包含多个分子结构及其下方/旁边文本标识的图片。
2. **分子 index 列表**：包含图像中检测到的分子的 index 编号（由任务上下文提供）。
3. **图注内容**：图像下方的标题（如 "Figure 1. Structures of reported..."），用于确定这些分子的共同类别。

---

## ⚠️ 分子标识统一规则 (mol_id / reference)

1. **mol_id**：当前条目所对应化学结构 bbox **右上角的蓝色数字 index**（整数）。它只是图像内的定位索引，不保证 bbox 是完整分子；母核、完整分子和取代基片段都可以有各自的 `mol_id`。
2. **reference**：该分子在**论文/图注中的文字指代符**（字符串），如编号 "(1)", "(2)", "YM-254890", "FR900359"。
3. **判定优先级**：
   * 结构式存在 → 必须记录 `mol_id`；
   * 无结构式、有文字指代符 → 记录 `reference`；
   * 二者都存在 → **同时记录 `mol_id` 和 `reference`**；
   * 均无 → 填 `null`。
4. **严禁输出 SMILES**：任何字段不得包含 SMILES / 结构式 / 分子式字符串，分子结构一律用 mol_id 指代。

### 候选 index 真实性校验（强制）

* 上下文提供的 index 只是 YOLO 产生的**候选 bbox**，可能是误检，不代表框内一定存在分子。
* 写入任何 `mol_id` 前，必须直接检查该 bbox 内是否能看到连通的化学结构表达，例如明确的化学键骨架、原子标注或环结构。蓝色 index、红色框或候选列表本身都不能作为分子存在的证据。
* 文字、数字、表格内容、图例、统计符号、坐标元素、箭头、蛋白示意及装饰线均不是分子结构；例如 `Cmax`、`Cmax/dose` 即使被框选也不得引用其 index。
* 若 bbox 明显不是分子或无法确认，**不得在输出的任何位置出现该 index**，不得仅因候选 index 存在而创建 `molecules` 条目。若有效的名称或论文编号仍存在，可只记录 `reference`，将 `mol_id` 置为 `null` 或按 schema 省略。
* 允许候选 index 不出现在最终 JSON；不得为了覆盖所有候选框而强行分配。母核、整分子和作为整数引用的取代基都必须独立通过该校验。

---

## 📝 核心指令 (Core Prompt)

### 步骤 1: 语境理解

1. **提取元数据**：阅读图注（Caption），识别这组分子的共同背景（例如：G$\alpha$q/11 protein inhibitors）。将此信息记录在 `figure_context` 字段。

### 步骤 2: 结构与文本关联

对图像中出现的每一个分子，执行以下识别逻辑：

1. **识别数字编号**：寻找分子下方的括号内或加粗的数字或者字母编号（如 (1), (2), (3)），写入 `reference`。
2. **提取名称/代号**：提取数字编号前的文本名称（如 YM-254890, FR900359），写入 `common_name`。
3. **引用分子 index**：分子结构通常被检测框包围且**右上角有蓝色 index 数值**，根据该分子在图像中的位置，用对应的 **mol_id** 引用该分子。
   * **⚠️ 物理位置校验**：确保提取的文本（名称和编号）在视觉位置上位于该分子结构的正下方或紧邻位置，防止错配。

### 步骤 2.5: 统一分子表达

所有分子（整分子、母核、取代基）**统一放入 `molecules` 数组**：

* **整分子**：独立完整分子（检测框 + 右上角蓝色 index），直接作为一个条目。
* **母核（带取代基位点）**：若某分子是母核骨架且带有 R1/R2 等取代基位点，在同一条目内用 `substituents` 描述：
  * 取代基被**红色框包围**且**右上角有蓝色 index 数值** → 用该蓝色数字作 mol_id 引用；该取代基本身还必须作为 `molecules` 中的独立条目，独立条目的 `mol_id` 与母核 `substituents.R*` 使用同一个 index。
  * 取代基**无框无数字**（仅简称/分子式，如 "Me", "Cl", "H"）→ **直接写入**该文字/简称。
* **不得错绑**：母核条目的 `mol_id` 只指向母核 bbox，不能使用某个取代基 bbox；取代基独立条目的 `mol_id` 也不能继承母核 index。`reference` 与实际 bbox 的空间对应关系必须逐项确认。

### 步骤 3: 异常处理

* 如果某个分子只有编号没有名称，`common_name` 填入 `null`。
* 如果某个分子有多个名称（如通用名和实验代码），请一并提取。

---

## ⚠️ 识别操作限制

1. **结构与文本必须位置对应**：文本（编号/名称）与分子结构的空间位置必须匹配（正下方或紧邻），不得跨分子错配。
2. **只读图注与图像内文字**：不得引用正文中未在该图上出现的编号。
3. **键名与图注一致**：`substituents` 的键名根据图中实际标注命名（如 R^a, X, HetAr），不要局限于 R1/R2。
4. **严禁幻觉**：图像模糊无法确认或对应 index 缺失时，填 `"Unclear"` / `null`。
5. **仅输出 JSON**：不得包含任何解释文字。

## 💻 输出格式要求 (JSON)

```json
{
  "figure_context": "Figure 1. Structures of reported Gαq/11 protein inhibitors.",
  "molecules": [
    {
      "reference": "scaffold",
      "common_name": "通用母核",
      "mol_id": 0,
      "role_in_paper": "母核骨架",
      "substituents": {
        "R1": "Me",
        "R2": 1
      }
    },
    {
      "reference": "1",
      "common_name": "YM-254890",
      "mol_id": 1,
      "role_in_paper": "reported inhibitor"
    }
  ]
}
```

> **取值规则**：
> * `mol_id` / 取代基整数值 = 图像中对应分子结构检测框右上角的**蓝色数字 index**。
> * `mol_id` 本身不表示完整性；条目和字段关系决定该 bbox 是完整分子、母核还是取代基。
> * `reference` = 论文/图注中的文字编号或名称，有结构时与 `mol_id` 同时记录。
> * 取代基字符串（如 "Me", "Cl"）= 无框无数字的化学简称。
> * 所有分子（含母核、取代基）统一在 `molecules` 数组内；母核分子可带 `substituents` 字段。
