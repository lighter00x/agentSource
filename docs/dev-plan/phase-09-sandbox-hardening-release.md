## 1. 目标

1. **沙箱**：一次性容器执行第三方 Skill、用户私有 Skill 和 Agent 自写代码；补救动作加入 `run_code`；代码沉淀为用户私有 Skill。
2. **负载保护**：准入控制、公平调度、负载降级 L1～L3。
3. **质量与性能**：评测（银标准与对照实验）、压测、容量数据、故障恢复。
4. **安全加固**：SSRF、RLS、密钥、沙箱、提示注入的专项检查。
5. **发布**：演示脚本跑通，交付文档。

## 2. 范围

**做**

- 沙箱池：预热的空白容器，分配时注入输入与令牌，用后销毁；`skill` 池与 `agent_code` 池分开；按用户和论文的配额。
- JSON-RPC over stdin/stdout；`drugpaper_sdk`（只读能力）；Tool Broker 校验令牌、白名单与预算。
- `run_code` 补救动作：代码生成（只附相关 SDK 速查）、AST 静态检查、执行、输出按目标 Schema 校验、再走 L1 自检；每 Agent ≤ 2 次、每篇 ≤ 5 次。
- 第三方与用户私有 python 型 Skill 在沙箱中执行。
- 代码沉淀：同类问题多次成功后提示打包，自动生成 manifest、triggers、L1 草稿和测试用例；用户确认后进入私有 Skill 库。
- 准入控制、按用户分桶的公平调度、负载降级 L1～L3（按排队等待 P95 自动切换）。
- 评测：银标准对比、对照实验 A/B/C、各层指标（设计文档 20.2）。
- 压测：批量 100 篇，按阶段统计耗时与调用；各档位并发占用；容量估算与设计文档 18.4 对比。
- 故障注入：Worker 崩溃、模型超时、MinerU 不可用、用户模型失效、数据库短暂不可用。
- 安全检查清单。
- 演示与交付文档。

**不做**

gVisor/Firecracker（接口预留）、Kubernetes 部署（P2/P3 规模化阶段）。

## 4. 关键设计要点

### 4.1 沙箱隔离边界

| 维度 | 边界 |
|---|---|
| 数据权限 | 代码只能读 Agent 显式传入的材料和该节点的只读资产 |
| 运行环境 | 单次执行一个全新容器，用后销毁；同一 Agent 的两次执行也不共享 |
| 资源配额 | 每用户同时 ≤ 4 个沙箱；每篇 `run_code` ≤ 5 次；每次 30 s、512 MB |
| 网络 | `--network none`；模型调用不在白名单内 |
| 硬约束 | 容器永不跨用户复用 |

### 4.2 AST 静态检查

禁止：`os.system`、`subprocess`、`socket`、`ctypes`、写模式 `open`、`eval`、`exec`、动态 `__import__`、访问 `__builtins__` 的反射技巧。检查不通过直接拒绝执行，并把原因反馈给代码生成（算 1 次修正）。

### 4.3 负载降级

| 级别 | 触发（排队等待 P95） | 调整 |
|---|---|---|
| L0 | < 30 s | 全部开启 |
| L1 | 30～120 s | 补救限 1 轮；禁用 `run_code` 和视觉回查 |
| L2 | 120～300 s | 取消定向复核；L2 自检只对 L1 有告警的图执行 |
| L3 | > 300 s | 关闭 L2 自检和补救；回查只用 grep/search；暂停批量准入，交互不受影响 |

级别写入文档质量报告；降级处理的文档可以一键"补做复核"。

### 4.4 评测

- **银标准**：10 篇以上现有流水线产物（人工抽检后使用）。
- **对照实验**：A 现有流程；B 本系统语料 + 现有 prompt；C 本系统完整流程（设计文档 20.3）。
- **指标**：版面、分子、表格、图表、化合物、路径、输出、性能（设计文档 20.2）。
- 输出评测报告，作为后续迭代的基线。

## 6. 安全检查清单

| 项 | 检查方法 |
|---|---|
| SSRF | 回环、元数据、平台保留地址、DNS 重绑定、重定向、公网 http，全部被拒；内网推理服务可接入 |
| 用户隔离 | 跨用户访问文档、Artifact、Blob、对话、Skill、模型配置，全部 404；RLS 兜底测试 |
| 密钥 | 接口、日志、RunRecord、错误信息、缓存键中无明文；轮换后旧密钥失效 |
| 沙箱逃逸 | 网络访问、写宿主文件、读其他容器、fork 炸弹、超时、超内存，全部被阻止并记录 |
| 提示注入 | 在测试 PDF 中嵌入"忽略之前的指令"类文本，确认 Agent 不执行、不越权；用户 Skill 描述中的注入被过滤 |
| 内部服务认证 | 不带服务令牌访问 MinerU、MolDet、MolParser、平台推理服务、管理接口，全部被拒 |
| 管理接口 | 普通用户访问 `/admin/*` 被拒 |

## 7. 演示脚本（D15）

1. 批量提交 10 篇论文，展示进度与降级级别。
2. 打开样例论文工作台：PDF 定位、分子框、表格与图表视图、结果 JSON 与证据回跳。
3. 展示一张图的 AgentTrace：三次调用、自检告警、补救、通过。
4. 展示阅读过程：逐页笔记、批量回查的问题与答案。
5. 对话提问，回答带引用；在对话中提出纠正一个分子，确认后 JSON 自动更新。
6. 重跑一张图表；从第 k 页重读。
7. 用户在模型设置页接入自有 API：填错密钥被拒；正确配置后绑定到阅读阶段，处理一篇文档并查看"模型来源"。
8. 管理员替换平台某阶段的模型，发布并回滚。
9. 展示评测报告与压测数据。
