# P7：模型管理与用户

> 周期：D5～D10 ｜ 负责人：BE-1（主）、FE-2 或 BE-1（登录与身份的前端部分）
> 前置：P2 的数据库与 API；P3 的 `ModelClient.chat(task=...)` 与 Skill 作用域
> 设计文档对应：18.2 模型管理与网关（18.2.1～18.2.8）、19.1 安全、19.4 用户数据隔离、D32～D34、D39～D41

---

## 1. 目标

1. **用户隔离**：系统能识别用户，每个用户的文献、结果、配置、Skill 严格隔离。
2. **模型管理**：五层注册表（提供方 → 模型 → 池 → 阶段 → 任务）以数据库为权威来源，支持版本、草稿、校验、测试、发布、回滚。
3. **模型网关**：按任务解析到阶段和模型；限流、主备、熔断、健康检查、计量、配额。
4. **用户自定义推理 API**：platform / custom / hybrid 三种模式，添加时检查可用性，出站代理防 SSRF，密钥信封加密。

## 2. 范围

**做**

- 用户与身份：`users` 表、API Key、Web 登录换取短期令牌、管理员角色。
- 隔离：所有业务表的 `user_id`、PostgreSQL 行级安全（RLS）、BlobStore 按用户分区、模型缓存按用户命名空间、访问他人资源返回 404。
- 注册表：数据库表、YAML 导入导出、版本与草稿、发布前校验（引用、能力、限制、强度）、热加载。
- 能力探测与可用性检查。
- 网关：阶段解析、按模型部署的信号量（交互预留）、主备回退、熔断、健康检查、`model_calls` 计量、用户配额。
- 提供方适配器：`openai_compatible`（结构化输出降级链、思考开关、grounding 坐标换算、token 字段、错误映射）。
- 用户自定义模型：`/me/models` 接口、添加时可用性检查（不通过不保存）、能力探测回填、阶段绑定、文档级配置快照、用户独立限流、回退策略（默认 pause，`waiting_user_model` 续跑）。
- 出站代理：内网允许、平台保留地址禁止、回环与元数据地址始终禁止、连接时 DNS 校验、不跟随重定向、公网仅 https。
- 密钥：信封加密（用户数据密钥 + 主密钥）、只写不读、末 4 位提示。
- 平台内部服务的服务间认证（纵深防御）。
- Skill 的 `user` 作用域启用。

**不做**

管理台页面（P8）、质量体验对比与灰度发布（可削减，放在 P8 末尾或 P9）、其他提供方类型的适配器。

## 4. 关键设计要点

### 4.1 解析顺序

```text
resolve(task, user, document):
  snapshot = document_model_snapshot(document)          # 文档开始时固定：平台版本 + 用户版本
  stage = snapshot.system.tasks[task].stage
  if 用户模式为 custom，或 hybrid 且覆盖了 stage:
      候选 = 用户绑定的模型（+ 用户备用）[+ 平台模型，若双方都允许回退]
  else:
      候选 = 平台该阶段的模型链
  参数 = 平台任务参数 + 用户允许修改的参数
```

### 4.2 添加模型时的可用性检查

同步执行，任一项失败即返回 422，不保存：地址规则 → 连通性与 TLS → 认证 → 模型名存在 → 最小推理请求。通过后自动做能力探测（视觉、结构化输出模式、grounding 坐标格式、思考开关、延迟），结果决定可绑定的阶段。已保存的模型每天复检；熔断时立即复检。

### 4.3 出站代理规则

| 目标 | 处理 |
|---|---|
| 公网地址 | 允许，仅 https |
| 私有网段（10/8、172.16/12、192.168/16） | 允许，可用 http |
| 回环、链路本地、云元数据 | 始终禁止 |
| 平台保留地址（services.yaml、平台注册表、数据库、Redis 的全部地址 + 管理员追加） | 禁止 |
| 重定向 | 不跟随 |
| DNS | 连接时解析，按解析出的 IP 判定 |

### 4.4 隔离的实现层次

API 归属校验（404）→ RLS 兜底 → Blob 路径分区 → 缓存键含 `user_id` → 检索带 `user_id` 过滤 → 队列按用户分桶 → 日志带 `user_id` 且脱敏。

## 6. 测试

| 类别 | 用例 | 期望 |
|---|---|---|
| 隔离 | 用户 A 请求用户 B 的文档 | 404 |
| 隔离 | 应用层故意漏写 user 过滤的查询 | RLS 仍然只返回本用户数据 |
| 注册表 | 结构化阶段绑定一个无 grounding 能力的模型 | 发布前校验失败 |
| 注册表 | 发布新版本 → 回滚 | 热加载生效；回滚生成新版本号 |
| 网关 | 主模型熔断 | 请求走备用模型；`vlm_strong` 不回退到 `vlm_light` |
| 网关 | 批量请求占满槽位时发起交互请求 | 交互请求使用预留槽位，不排队 |
| 用户模型 | 添加时填错密钥 | 422，提示"密钥无效或无权限"，不保存 |
| 用户模型 | 添加时填错模型名 | 422，列出服务端可用模型名 |
| 用户模型 | hybrid：只覆盖阅读阶段 | 阅读走用户模型，其他阶段走平台模型 |
| 快照 | 处理中途修改用户配置 | 当前文档不受影响 |
| 回退 | 用户模型在处理中失效，策略为 pause | 文档进入 `waiting_user_model`；修复后续跑，已完成步骤不重做 |
| SSRF | base_url 为 127.0.0.1、169.254.169.254、平台数据库地址、MolParser 地址 | 全部拒绝 |
| SSRF | 域名解析到内网平台地址（模拟 DNS 重绑定） | 连接时拒绝 |
| SSRF | 用户内网的推理服务地址（非平台保留） | 允许 |
| SSRF | 公网 http 地址；重定向到内网 | 拒绝 |
| 密钥 | 查询接口、日志、错误信息、RunRecord | 不出现密钥明文 |
| 计量 | 用户模型调用 | `billing_owner=user`，不计入平台配额 |

## 7. 验收标准

- [ ] 两个用户各自上传文档，互相不可见，RLS 测试通过。
- [ ] 管理员通过接口替换平台某阶段的 base_url 和 model_name，校验、测试、发布后热加载生效，可回滚。
- [ ] 用户通过接口添加自有模型：错误配置被拒绝并给出原因；正确配置添加成功并自动探测能力；绑定到阅读阶段后处理一篇文档，结果标注模型来源。
- [ ] SSRF 测试全部通过；内网推理服务可接入。
- [ ] P1～P6 的所有模型调用都经过网关，`model_calls` 中能按阶段、模型、用户、`billing_owner` 统计。
- [ ] 接口冻结：注册表 Schema、`/admin/models/*`、`/me/models/*`、`model_calls` 字段。

## 8. 风险

| 风险 | 对策 |
|---|---|
| 给已有表加 RLS 影响现有查询 | 连接池统一设置 `app.current_user_id`；后台任务使用明确的用户上下文；集成测试覆盖所有 Repository |
| 不同推理服务的 OpenAI 兼容程度不一 | 能力探测识别实际能力；适配器的降级链兜底 |
| 出站代理成为瓶颈或单点 | 只代理用户模型的请求；代理无状态、可多实例 |
