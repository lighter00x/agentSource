## 1. 目标

1. **工作台**：用户在 PDF 上查看解析结果，点选节点，查看证据、表格、图表、分子、阅读过程和 Agent 执行过程。
2. **对话**：单篇论文内的开放式问答，回答带引用；可以在对话中提出纠错或重跑，需用户确认。
3. **纠错与重跑**：以 Work Unit 为最小粒度，确定性下游自动更新，模型下游标记 stale 供用户选择。
4. **模型管理台**：用户"模型设置"页和管理员页。

前端从 D3 起用 Mock 接口并行开发，后端接口就绪后逐个切换，这是一个贯穿全程的阶段。

## 2. 范围

**做**

- 工作台组件：PdfViewer + SVG Overlay、文档树、化合物面板、Inspector、TableView、ChartView、ResultView、阅读过程视图、AgentTrace、协作面板、SmilesEditor、RerunDialog、ChatPanel。
- 对话 Agent：基于 P1 的 AgentRuntime + P3 的 DisclosureToolset；常驻工具 + 元工具 + 动态激活；引用校验；`interrupt` 等待用户确认；SSE 流式输出；会话持久化。
- 纠错：Correction 模型与 API、锁定与解锁、冲突与解决、撤销。
- 重跑规划器：从 Correction 或 RerunRequest 找出直接影响的 Work Unit，沿依赖边遍历下游；确定性下游自动执行，模型下游标 stale；预览接口（`dry_run`）。
- `rerun_graph`：在 interactive 队列中执行；支持整图重跑（`figure_agent:<node>`）、单 Skill 重跑、从第 k 页重读。
- 模型管理台：用户页（模式、提供方、模型、能力探测、阶段绑定、回退策略、用量、版本）；管理员页（平台配置、发布与回滚、审计、自定义模型策略、健康与用量）。

**不做**

Ketcher 分子编辑器（后续）、跨篇对话、灰度与评测的管理台页面（若 P7 削减）。

## 4. 关键设计要点

### 4.1 对话 Agent

- 常驻工具：`grep`、`search`、`get_node`、`get_compound`、`query_measurements`，以及 4 个元工具。
- 按用户问题和 UI 焦点预选能力（L0 目录，高相关附 L1）；其余能力由模型发现后激活，同时最多 6 个。
- `lookup` 走 DocLookup 批量回查，检索过程不进入对话上下文。
- `propose_correction` / `request_rerun` 触发 `interrupt`，UI 展示修改前后对比与重跑计划，用户确认后执行。
- 引用必须来自本轮工具结果，不满足的删除并提示。
- 预算：每轮 ≤ 12 次工具调用、`look_at` ≤ 2 次、能力描述 ≤ 2.5K tokens、上下文 ≤ 24K tokens。

### 4.2 重跑规划

按设计文档 13.3 的伪代码实现，并覆盖 13.4 的全部场景：

| 场景 | 立即执行 | 自动更新 | 标记 stale |
|---|---|---|---|
| 手动输入某分子 SMILES | 无 | 化合物 → 步骤片段 → 投影 | 无 |
| 某分子重识别 | 1 次 OCSR | 同上 | 无 |
| 调整分子框 | 重裁剪 + 1 次 OCSR | 同上 | 无 |
| 编号绑定错误 | 无 | 化合物结构重选 → 步骤 → 投影 | ReaderAgent 综合 |
| 表格重抽取 | 结构化 + 自检 | 测定 → 化合物 → 投影 | 综合（仅提示） |
| 单元格修正 | 无 | 投影 | 无 |
| 图表重数字化 | 结构化 + 自检 | 估计测定 → 投影 | 无 |
| 整张图重新理解 | 该图 FigureAgent | 该图全部事实 → 增量归一 → 投影 | 综合（主路线化合物变化时） |
| 修正优化路径 | 无 | step_builder → 投影 | 无 |
| 从第 k 页重读 | 第 k 页之后的阅读 + 综合 | step_builder → 投影 | 无 |

## 6. 测试

| 类别 | 用例 | 期望 |
|---|---|---|
| 重跑 | 手动修改化合物 26 的 SMILES | 只有该化合物、涉及它的步骤、JSON 相关字段更新；依赖记录可查；无模型调用 |
| 重跑 | 对某分子框重识别 | 1 次 OCSR；其他分子 ID 与纠错不受影响 |

## 10. 本期开发调试需求基线（2026-11-20）

完整前端交互见[总体设计 17.6](../drug-paper-agent-detailed-design.md#176-开发调试工作台已确认需求2026-11-20待实现)，配套后端设计见同文档 13.7；实施步骤和验收见[执行方案新增调试范围](execution/phase-08-execution.md#2026-11-20-新增执行范围全过程开发调试待开发)。

1. 阶段细分导航 + 全流程工作区，同步选中文献、图表和运行；原始 PDF 位于调试主区左侧，详情/编辑位于右侧。
2. 仅渲染 MinerU 合并后的图表布局，不重复显示 body/caption/footnote 原始成员；保留独立文本及 OCR，原始关系可查。跨页图表作为整体，暂不做父子图交互。
3. 上传前预设模式：自动模式执行 MinerU 及所有图表解析；手动模式仅执行 MinerU，点击单图解析后自动分类→选 Skill→执行，不要求人工选择 Skill。独立分类及 Skill 指定仅作额外调试入口。
4. 每一步可查看输入输出、图像、实际请求响应、Skill/工具及代码版本、模型、耗时和错误；支持执行到、执行前暂停、继续和从某步重跑。
5. 全 Skill 包及相关公共工具代码可编辑，先作用于当前文献当前图表，局部试运行后主动更新全局；保存历史快照和差异，避免局部编辑污染全局。
6. 分子默认按需处理，预处理入口灵活可配。点击 PDF 上分子框，在右侧展示分子式、SMILES、标准渲染，渲染不可用用截图；不完整结构保留状态，不编造分子式。
7. 人工修正仅含分子框增删调整、SMILES、图表类型并重新路由。默认采用人工版本，保留并可恢复机器原始结果。不加入单元格/提取字段及分子关联关系编辑。
8. 重跑新建运行并继承有效上游；分子检测识别正确时只执行后续步骤。上游变更使相关下游过期，明确复用来源并保留多次结果用于比较。
9. 自动模式单图失败/待复核不阻塞其他图表；汇总成功、失败、待复核等数量，可仅重试问题图。

实施优先打通「合并布局→单图自动分类/路由→逐步查看→分子修正→局部重跑与比较」，再接整篇自动调度及全局发布。不得将新增设计写作既有功能，P5/P6 内容准确率与完整 P8 验收状态保持原记录。


## 2026-11-22：单图 Agent 探索调试

结构化阶段新增“Agent 探索过程”，按发生顺序显示决策、工具开始、工具返回和停止原因；详情用现有代码编辑器 JSON 查看器展示。常规模型请求/响应与 Skill 记录继续保留，便于核对模型是否真正看到检索证据和关联图像。工具开始事件在执行前写入，长请求期间也可知道正在等待哪项操作。

单图 Agent 可自主选择全文读取/搜索、关联图像查看、当前 Skill 提取、当前图分子重识别和回填校验；不是按固定关键词依次搜索。出现未解决问题时，未经取证不得直接以待复核结束；新增证据后必须重提取和校验。探索预算结束仍可返回已有结果，但标明待复核；最终 L2 审核独立执行。

完整结果 JSON 保存 `exploration`（文献/版本/可修改图范围、证据、工具记录、预算用量、状态与结束原因）；工具调用不越过当前文献，写入不越过当前图。预算可通过后端 FIGURE_EXPLORATION 配置控制，详情见 P5 实现文档末节。局部重跑以 structure 为入口，已有分子预处理可按现有材料一致性检查复用。
